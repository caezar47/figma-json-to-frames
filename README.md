# JSON to frames

Плагин для Figma, который **подставляет данные из JSON в заранее подготовленный макет** и создаёт набор готовых фреймов (по одному на каждый объект в массиве).

Ниже — как устроен процесс **с точки зрения дизайнера**, без технических деталей реализации.

## Локальная установка в Figma Desktop

Плагин **не публикуется** в Community Figma; подключение идёт из копии репозитория на вашем компьютере.

1. **Скачайте исходники** с [GitHub: caezar47/figma-json-to-frames](https://github.com/caezar47/figma-json-to-frames) — **Clone** (`git clone`) либо **Code → Download ZIP** и распакуйте папку в удобное место.
2. Откройте **Figma для десктопа** (в браузере путь **Plugins → Development** может отличаться или быть недоступен — ориентируйтесь на **десктопное приложение**).
3. **Plugins** → **Development** → **Import plugin from manifest…** — укажите файл **`manifest.json`** в корне склонированной/распакованной папки.
4. Запуск: **Plugins** → **Development** → **JSON to frames** (имя взято из манифеста).

**Демонстрационный шаблон** в Figma: [страница с примером макета](https://www.figma.com/design/eK9JYNmjCIpPZZou5qq1oG/base?node-id=11548-7380&t=gjmhOeVagGUPZwu3-1) (можно скопировать в свой файл и подставлять JSON по инструкции ниже).

## Зачем это нужно

Когда у вас есть **повторяющаяся сетка карточек, спецификаций, прайс-листов** и т.п., вручную копировать фрейм и менять тексты и картинки долго и чревато ошибками. Плагин берёт **один шаблон** в файле Figma и **массово заполняет** его из табличных данных, представленных в формате JSON.

## Как устроен рабочий процесс

1. **Подготавливаете шаблон** — фрейм (или группу) на странице с точным именем, например `TEMPLATE`. Стили (шрифты, цвета, отступы) задаёте **в Figma** как обычно: плагин не «рисует» стиль с нуля, а использует **ваш** макет.
2. **Помечаете слои, куда подставляются поля** — в имени слоя используется соглашение с префиксом `[data]…` (см. раздел ниже).
3. **Открываете плагин** и вводите:
   - **имя узла шаблона** — должно **точно совпадать** с именем фрейма шаблона на странице (по умолчанию в поле стоит `TEMPLATE`);
   - **поле JSON для имени клона** — например `sku`. Для каждой строки данных плагин создаёт копию шаблона; **имя этой копии** берётся из выбранного поля. Если оставить логику «как у шаблона», имя клона остаётся таким же, как у оригинала (часто тоже `TEMPLATE` — клоны всё равно будут отдельными узлами на странице);
   - **JSON** — массив объектов, например список товаров, где у каждого объекта свои поля: заголовок, артикул, числа, ссылка на фото и т.д.
4. Нажимаете **«Сгенерировать»**. Плагин **для каждого элемента массива** дублирует шаблон и подставляет в размеченные слои значения из соответствующих полей JSON.

## Как из Excel сделать JSON

Данные чаще всего приходят **таблицей в `.xlsx`**. Плагину нужен **массив объектов** — как в примере в окне плагина. Удобный путь: подготовить лист в нужном виде и прогнать его через конвертер **[Excel to JSON (excel2json.io)](https://excel2json.io/)**, затем вставить полученный JSON в поле плагина.

### Какой должна быть таблица (файл «для генератора»)

Конвертеры вроде excel2json.io обычно ожидают **одну плоскую таблицу на листе**:

1. **Первая строка** — **имена полей JSON** (заголовки колонок). Они должны **совпадать** с ключами, которые вы заложили в шаблон Figma: `[data]title` → колонка `title`, `[data]sku` → `sku` и т.д.  
   - Лучше **латиница, без пробелов** в названии колонки (`attr1`, `photo`) — так проще и для Excel, и для JSON.  
2. **Каждая следующая строка** — **одна запись** (один будущий фрейм/карточка). Строка становится **одним объектом** в массиве.  
3. **Нет «красивой вёрстки» в зоне данных** — **без объединённых ячеек** в таблице, без лишних пустых строк внутри данных. Пустая ячейка чаще всего превратится в пустую строку `""` (а не `null`); если нужен именно `null` для скрытия группы, поле при необходимости правят уже в готовом JSON.  
4. **Одна сущность в строке** — все поля, которые уходят в один объект, лежат **в одной строке** (плоская таблица, без вложенных подтаблиц в одной ячейке).

### Почему исходный файл часто нельзя скормить сразу

Рабочий выгрузочный `.xlsx` (условно `origin.xlsx`) нередко устроен иначе: объединённые ячейки, несколько уровней заголовков, подписи сбоку, пустые столбцы-разделители, **неподходящие имена колонок** для JSON. Тогда таблицу **вручную приводят** к «плоскому» виду (условно `edit.xlsx`): одна шапка-ключ, одна логическая строка на объект, колонки переименовывают под финальные ключи.

Схема в двух шагах:

1. **Исходник** → **упрощение** до одной плоской таблицы с нужными колонками.  
2. **Файл в формате «для генератора»** → **[excel2json.io](https://excel2json.io/)** → копируете **массив** ` [ {...}, ... ] ` в плагин.

В проекте в каталоге `fid` для ориентира лежат `origin.xlsx` (исходник с выгрузки) и `edit.xlsx` (тот же материал **приведённый вручную** к плоскому виду «одна строка — один объект»). Сверяйтесь с **`edit`**: требования к листу выше описаны по его логике, а не по «кривой» вёрстке `origin`.

При смене имени шаблона в поле интерфейса плагин может выполнить **превью**: проверяется, что узел с таким именем на странице **существует** (само заполнение по превью не делается — это лишь проверка).

## Как называть слои, чтобы плагин их нашёл

### Текст и обычные поля

- Слой с **`[data]ключ` в имени** — в него подставляется **строка** из JSON по полю `ключ` (как в примере: `[data]title`, `[data]attr1`).

### Условные блоки (показать / скрыть)

- **Фрейм** с именем вида **`[data][group]ключ`**: весь фрейм **скрывается**, если в JSON у поля `ключ` значение **`null`**, либо **такого поля нет**. Так можно прятать целые группы (например блок «скидка»), когда данных нет.

### Картинки

В поле JSON может быть **URL картинки** или **точное имя другого слоя** на **этой же странице**, у которого уже есть **заливка-картинка** (как встроенный ассет в макете). Опционально такое имя можно указывать с префиксом `figma:`.

Так дизайнер может либо тянуть изображения по ссылкам из данных, либо переиспользовать уже настроенные в файле плейсхолдеры.

## Поведение при ошибках и пустых данных

- **Текст** (`[data]ключ`): при `null` или **проблеме со шрифтом** слой **скрывается** (показ не «ломается» пустыми квадратиками, если глифа нет).
- **Картинка по URL**: при ошибке загрузки (часто из‑за **CORS** на стороне хоста) слой **скрывается**, в интерфейсе может появиться **предупреждение**, но **вся генерация не прерывается** — остальные карточки досоздаются.

## Сеть и данные

Плагин может запрашивать изображения **по произвольным URL** из полей JSON (как в манифесте: хосты задаёт пользователь в данных). Имейте в виду ограничения **CORS** на стороне сервера картинок — в этом случае сработает сценарий «слой скрыт + предупреждение» выше.

## Кратко

| Что | Действие дизайнера |
|-----|--------------------|
| Установка | [Репозиторий](https://github.com/caezar47/figma-json-to-frames) → в Figma **Desktop**: **Import plugin from manifest** (`manifest.json`) |
| Шаблон | Один фрейм с устойчивым именем, стили в Figma |
| Разметка | `[data]поле` в имени слоя, группы — `[data][group]поле` |
| Данные | JSON-массив объектов, поля совпадают с ключами в именах |
| Имена копий | Поле вроде `sku` (или пусто = имя как у шаблона) |
| Картинки | URL в JSON **или** имя слоя с картинкой на странице (`figma:` по желанию) |
| Excel → JSON | Плоский `.xlsx`: строка 1 = ключи полей, далее по строке на объект; конвертация в [excel2json.io](https://excel2json.io/) |
